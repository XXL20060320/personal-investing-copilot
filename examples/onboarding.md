# 示例 1：从余额宝起步，场内该怎么配

> 演示起步引导主线的完整执行链。示例中的金额与比例均为**用户自述 / 脚本计算 / 规划假设**，不是市场数据。

## 用户说

```
我钱基本都放余额宝，大概 12 万，每月能存 2000，
每月固定开销 5000，想开始配点场内 ETF，该怎么弄？
```

## 应该发生什么

1. 读 `references/onboarding-and-allocation.md` → `references/output-templates.md`。
2. 跑 Step 0：资金分层（用户已给总额、月开销、月结余）、风险承受用具体情景追问（一次最多 3 个问题，例如「投入 10 万一年后变 8 万会不会立刻卖」）、场内就绪度（是否已开户）。
3. 用 `scripts/allocation_calc.py` 算三层桶、目标比例、每期金额、再平衡阈值、下跌情景压测；输出标注「依据用户提供的数值计算」。
4. 明确「先补齐应急金 → 核实开户与场内规则 → 小额试运行 → 6–12 个月分批」路径；**只有第 2 层长期钱谈权益 ETF**。
5. 场内规则清单只列「必须向券商 / 交易所核实什么」，不写具体数值。
6. 附 `references/beginner-explainer.md` 的白话解释（三层桶、分批、再平衡各一句「所以呢」）。
7. 定稿前按 `references/release-gates.md` 门控 → 末尾附固定免责声明模板 A。

## 门控检查点

- 命中 BLOCK：用户未给回撤承受就给满仓比例；把 12 个月分批写成「降低亏损风险」；写出具体佣金数值；免责声明后又追加一句话。
- 命中 NEED_REVIEW：应急金月数偏低但用户坚持长期钱足 → 结论范围缩小并下调置信度。
- 边界场景：若总额 2 万、月开销 5000，`allocation_calc.py` 返回 `targets.not_applicable = true`、压测为空 → 必须解释为「先补应急金，暂不增加权益敞口」，**不能**说「建议权益比例 0%」。
