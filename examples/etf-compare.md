# 示例 2：两只 ETF 选哪个

> 演示 ETF 身份核对、七维对比与量化打分。**不预置任何费率、规模或行情数字** —— 全部要求运行时取数并标注来源与时点。

## 用户说

```
510300 和 159915 我该买哪个？另外现在这个位置贵不贵？
```

## 应该发生什么

1. 读 `references/etf-screening.md`；因问「贵不贵」并行读 `references/valuation-and-entry.md`。
2. 若用户处于起步阶段或涉及「买」，先跑 Step 0 前提确认（资金期限 / 应急金 / 回撤 / 月投额），不齐先追问。
3. 第 0 步身份核对：产品全称、标准代码、管理人、跟踪指数全称、产品类型、成立时间、上市交易所 → 每个数字带来源与时点。**两只跟踪不同指数，不能直接当作「同类二选一」**，需先说明它们承担的组合角色不同。
4. 按七维取数（一手来源优先），填对比表；估值分位必须给样本区间、口径与来源，样本不足就明说。
5. 用 `references/etf-screening.md` 第 3.1 节逐项打分（硬门槛 → +3/+1/0 加权 → 红旗校验），写明权重是规划假设。
6. 若用户明确问「现价」，且环境允许联网 → 按 `references/data-sources.md` 第 7 节调用 `scripts/quote_probe.py`，输出带 `as_of` / `quality_flag` 的快照；端点失败则降级回检索路由，禁止凭记忆填价格。
7. 定稿前按 `references/release-gates.md` 门控 → 涉及具体买入动作用免责模板 B。

```

（Step 0 结果；若用户没答回撤承受，先追问，不直接给买入结论）

| 项目 | A（标准代码） | B（标准代码） | 来源 + 时点 |

## 七维对比表
| 维度 | A | B | 判断依据 | 来源 + 时点 + 口径 |

| 维度（权重） | A | B | 依据 |
（硬门槛结果、+3/+1/0 规则、权重为可调整的规划假设）
```

## 门控检查点

- 命中 BLOCK：某只产品的规模 / 费率只有媒体二手数字却直接下结论；把「近一年涨跌幅」当跟踪误差；用近期涨幅排序推荐；未核产品类型就把杠杆产品混入对比表。
- 命中 NEED_REVIEW：估值分位样本只有 3 年；`quality_flag = fallback` 未说明；跨境产品未核实溢价率与时点。
- 注意：本示例**不给出任何具体费率、规模或价格**，这些必须运行时取得；示例中的空格是模板占位，不是待填的「估计值」。
