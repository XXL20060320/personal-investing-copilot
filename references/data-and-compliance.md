# 数据、来源标注与合规（data-and-compliance）

> 何时读：任何需要取数、解析用户文件、标注来源、处理口径分歧或输出操作建议的场景。本文件是硬约束的落地细则。

## 1. 数据源路由（禁止跳级）

| 优先级 | 来源 | 使用条件 |
|---|---|---|
| 1 | 用户已连接的金融类 MCP | 默认首选；包括用户自建的 aktools、CNEquity 等 MCP server。行情 / 财务 / 宏观 / 公告一律先走这一层；未连接时不得假设可用 |
| 2 | `domain_search` | 第 1 层未连接、未覆盖、报错或无结果时启用 |
| 3 | `WebSearch` | 前两层都拿不到时才用，必须标注媒体名 + 日期并说明非实时 |

降级时说明原因。委派 `domain_search` 只写一句话检索意图（标的/主题 + 大方向），例如「研究 A 股红利低波 ETF（512890）的整体情况」；不要拆成字段清单、不要要求它输出分析报告或表格。字段筛选、表格化、排序、深度分析由主 agent 拿回数据后完成。

若环境中已加载 `workbuddy-finance-skill`，以其检索路由表为准。

## 2. 用户上传文件的解析

| 文件类型 | 处理方式 | 注意 |
|---|---|---|
| 财报 / 年报 / 公告 PDF | 用 PDF 读取能力提取文字与表格；扫描件先看能否 OCR | 记录报告期、币种、合并口径、是否为更正后版本 |
| Excel / CSV 持仓或财务数据 | 用表格读取能力读原值，保留列名与单位 | 先确认单位（元 / 万元 / 亿元）、是否含现金、是否已去重 |
| 券商 / 基金App 截图 | 逐项读数并请用户确认关键金额 | 截图数字不得当作一手来源，标注「用户提供的截图，需核实」 |

解析出的数值一律标注「来源：用户提供的〈文件名〉，时点：〈报告期/导出日期〉」。用户提供的数字与公开来源冲突时，优先一手公开来源并显式说明分歧，不静默替换。

## 3. 来源标注粒度

- 同一表格 / 数据卡片共享相同来源、统计周期与口径 → 在表头、表尾或图注统一标注一次即可。
- 不同来源或不同周期的子项 → 分别标注。
- 每个关键结论都要能追溯到对应的数据块。
- 标注格式示例：`来源：XX 公司 2025 年年度报告（2026-03-28 披露），报告期 2025FY，合并报表口径`。

**来源质量分级**

- 一手来源：交易所公告、监管机构、公司年报/季报、基金管理人公告、基金定期报告 → 可直接采信，标机构名 + 发布日期。
- 非一手来源：财经媒体、研报引用、第三方平台二次引用 → 必须标「非一手来源，需核实原文」；研报另标机构 + 发布时间。不得与一手来源同等处理。

## 4. 口径与时间规则

- 先核对标的身份：公司名、代码、ADR、ETF、同名公司、A/H 两地上市主体不能混用。港股代码可能是 ETF、杠杆产品、牛熊证或结构化产品，查净值前先确认产品类型。
- 核对净利润 vs 归母净利润、扣非 vs 非扣非、同比 vs 环比、财年 vs 自然年、合并 vs 母公司。
- 跨市场财报同期对比按自然年季度对齐，或用 TTM 滚动四季消除财年定义差异。
- 回答「最新 / 今天 / 现价」前确认交易状态：盘前 / 盘中 / 盘后 / 休市，并给最近一次收盘时点。相对时间默认北京时间；美股事件同时给本地与北京时间。
- 当前周期数据尚未发布时使用最近已发布周期，明确写出数据截止时间；不得把历史数据表述为当前数据。
- 判断历史估值分位需要长周期（优先近 10 年，至少覆盖完整一轮周期），3 年分位不足以支撑「历史 70% 分位」这类判断；取数不足时说明样本区间与局限。

## 5. 多源冲突与数据缺口

- 同一指标出现两个数值：至少列两个来源，优先采信交易所 / 公司公告 / 年报等一手来源，显式说明分歧与采用的口径。
- 数据缺失：写「当前数据源未覆盖〈具体指标〉，最近可用时点为〈YYYY-MM-DD / YYYYQn〉」，并明确因此缩小了哪部分结论。禁止编数、禁止用「大约 / 估计」掩盖缺口。
- 研报或媒体给出的数字不得作为唯一依据下操作结论。

## 5.1 五类表述分开写

每个判断都要能看出它属于哪一类，避免把推算包装成事实：

| 标签 | 含义 | 写法示例 |
|---|---|---|
| 事实 Fact | 有一手来源、可核验 | 「据〈来源〉，2025FY 营业收入 X 亿元」 |
| 计算 Calculation | 由用户数据或脚本推出 | 「依据用户提供的数值计算，HHI = 0.42」 |
| 解读 Interpretation | 分析判断，带置信度 | 「倾向于认为现金流质量弱于利润增速」 |
| 情景 Scenario | 假设下的线性估算 | 「若权益部分下跌 30%，按当前仓位估算浮亏 X 元」 |
| 限制 Limitation | 数据缺口、口径、样本不足 | 「费率未取得，本结论不含费率比较」 |

同一段里混用而不加区分，等于把假设伪装成结论。脚本默认参数、风险档位映射、压测跌幅一律归为「可调整的规划假设」，不得写成市场事实或历史规律。

## 5.2 数据信封与运行日志

取数与文件解析统一按 `references/data-sources.md` 的字段契约记录「来源 + 时点 + 口径 + 质量标记」，用 `scripts/data_envelope.py` 承载；研报末尾给出紧凑的运行记录（来源清单、脚本与参数、失败与降级、数据截止时点、待核实事项）。任何 `quality_flag ≠ ok` 的数据都要在正文显式说明并下调置信度，不得隐藏降级。

## 5.3 可选行情探针的边界

`scripts/quote_probe.py`（支持 A 股 / 港股 / 美股）仅在用户明确询问现价 / 最新价、且环境允许联网时调用；只向公开只读端点发送标的代码，不发送持仓、金额、账户或任何个人信息。它返回的是快照，休市时为最近一次收盘，**交易状态与字段口径仍须运行时核实**。端点失败时脚本返回 `unverifiable` 与空数据，此时必须回到第 1 节检索路由，禁止凭记忆填写价格。该脚本不做历史 K 线、场外基金估值、复权计算，更不下单。

## 5.4 第三方代码与许可证

本 Skill 合规改编了若干 Apache-2.0 / MIT 开源项目的方法论与数据契约结构，并对许可证声明不完整的项目只采用事实性信息。引用范围、许可证全文与修改说明统一见 `THIRD_PARTY_NOTICES.md` 与 `licenses/`；不得把无许可证或许可证全文缺失的第三方实现代码并入本 Skill，也不得在研报里声称上游作者为本结论背书。**数据与方法的第三方署名不影响市场数据本身的来源标注**——每个数字仍按第 3 节标来源与时点。

## 6. 免责声明固定模板（原文照抄，禁止改写、缩减或省略）

**模板 A —— 包含配置建议、仓位比例、估值判断、财报结论等一般理财分析时**，在回复末尾附加：

> **免责声明**：以上内容基于公开数据和量化分析，仅供参考，不构成投资建议。市场有风险，投资需谨慎。任何投资决策应结合个人风险承受能力、资金状况和投资目标独立判断，必要时咨询持牌专业机构。过往表现不预示未来收益。

**模板 B —— 包含具体买卖价位、交易计划、止盈止损、加减仓动作时**，在回复末尾附加：

> ⚠️ **风险提示与免责声明**：本文/本对话内容仅为基于公开信息的分析讨论，不构成任何投资建议、理财建议或交易邀约。市场有风险，投资需谨慎。文中所涉标的、价位、策略均仅供研究参考，不保证分析准确性或完整性，不代表对任何投资结果的承诺。投资者应根据自身风险承受能力、投资目标和财务状况独立做出决策并承担相应风险。过往业绩不预示未来表现。

两个模板按输出中最"强"的建议择一使用；既有配置比例又有具体交易动作时用模板 B。模板必须位于回复最末尾，后面不再追加任何内容。

## 7. 输出前自检清单

- [ ] 数据是否按 1→2→3 级路由取得，降级原因是否说明
- [ ] 每个关键数字是否有来源 + 时点 + 口径
- [ ] 是否存在编造、凭记忆写出、或「待核实」标签掩盖的虚构数据
- [ ] 概念口径是否核对（归母 / 同比 / 财年 / 产品类型 / 代码格式）
- [ ] 操作建议前是否已列清四项前提
- [ ] 数据、结论、置信度是否自洽，是否存在相互矛盾
- [ ] 是否包含具体买卖、价位或仓位建议；若是，固定免责声明是否完整位于末尾
- [ ] 事实 / 计算 / 解读 / 情景 / 限制是否分开，规划假设是否已显式标注
- [ ] 运行日志、数据信封与 `quality_flag` 说明是否齐备
- [ ] 是否按 `references/release-gates.md` 完成 PASS / NEED_REVIEW / BLOCK 判定
- [ ] 起步阶段用户是否需要附 `references/beginner-explainer.md` 的白话解释

本清单是数据源与合规维度；完整的红线、五类数据质检与交付门控在 `references/release-gates.md`，输出前两份都要过。
