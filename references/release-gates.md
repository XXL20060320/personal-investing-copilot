# 交付前质检门（release-gates）

> 何时读：任何研报、配置方案、对比结论或操作框架输出之前。这是最后一道闸，不是写作模板。
>
> 本文件的门控分级与数据质检维度参考 MIT 项目 `claude-trading-skills`（`data-quality-checker` / `pre-trade-discipline-gate`）、MIT 项目 `anchor-and-tilt`（确定性与红旗校验）以及 Apache-2.0 项目 `china-stock-fund-analysis`（质量门槛），均按本 Skill 场景重写；署名见 `THIRD_PARTY_NOTICES.md`。

## 1. 三态门控

| 判定 | 含义 | 处理方式 |
|---|---|---|
| **PASS** | 全部硬性项通过，剩余限制已显式声明 | 正常输出 |
| **NEED_REVIEW** | 存在需人工复核的软性问题，但结论范围已相应缩小 | 输出时在「数据缺口 / 风险」段逐条写明，**不得**用「注意风险」一笔带过；置信度措辞下调 |
| **BLOCK** | 触碰红线 | **不得输出操作结论**；改为说明缺什么、需要用户补充或核实什么，或只交付不含动作的分析部分 |

一次输出里同时出现多种问题时，按最严重的一档处理。

## 2. 红线（命中即 BLOCK）

1. 任何行情、财务数字、费率、规模、日期、代码或产品名称是编造、凭记忆写出，或用「待核实」标签掩盖的虚构值。
2. 关键数字缺少「来源 + 时点 + 口径」，或来源层级未按 `data-and-compliance.md` 路由取得且未说明降级原因。
3. 涉及买 / 卖 / 加仓 / 减仓 / 换仓 / 仓位 / 配置比例，但 Step 0 的四项前提未列清就给了操作结论。
4. 输出含具体动作、价位或配置比例，却未把固定免责声明模板**原文**放在回复最末尾，或模板后还有内容。
5. 标的身份未核对（把场外联接当 ETF、杠杆产品当普通 ETF、名称相似就当同指数）。
6. 配置比例合计不等于 100%（或未按约定明确说明剩余部分去向）；金额与比例互相矛盾。
7. 把脚本里的**规划假设**（风险档位比例、再平衡阈值、压测跌幅）表述成历史规律、市场事实或收益预测。
8. 场内交易规则、费用、最小单位、交收制度凭记忆写出具体数值，而未运行时核实。
9. 行情端点失败或未调用，却给出「现价 / 最新价」具体数字。
10. 出现荐股、目标价、收益承诺，或把「数据缺口」的结论包装成完整分析。

## 3. 软性问题（NEED_REVIEW）

- 结论仅建立在非一手来源上，未标「需核实原文」。
- 任何 `quality_flag ≠ ok`（`fallback` / `partial` / `stale` / `conflicting` / `unverifiable`）未在正文声明。
- 估值分位样本区间过短（不足一轮完整周期）却仍给出分位数字。
- 多源数字冲突但只采用了其一，未列出分歧与采用理由。
- 用户是起步阶段，但输出里出现 HHI、跟踪误差、分位等术语而未附小白解释层。
- 使用用户上传的截图 / 手工表格数字，未标注「用户提供，需核实」。
- 缺少运行日志、「下一步检查」或跟踪提醒，导致结论不可复现、无法复核。

## 4. 五类数据质检（输出前机械过一遍）

| 类别 | 检查什么 | 典型错误 |
|---|---|---|
| 价格量级 | 单价、指数点位、金额的小数位数与量级是否自洽 | ETF 单价写成指数点位；万元 / 亿元混用 |
| 代码格式 | A 股 6 位、港股 5 位、美股 ticker；逐个带标准代码 | 000001 未说明是上证指数还是平安银行；只写简称 |
| 日期与状态 | 日期星期是否对得上；是盘前 / 盘中 / 盘后 / 休市；数据时点与披露日 | 休市日写「今日实时」；把报告期当披露日 |
| 比例与金额 | 比例合计、权重合计、金额与比例互相校验 | 三层桶金额加总不等于可投资产；目标比例合计 95% |
| 单位与口径 | 元 / 万元 / 亿元；同比 / 环比；归母 / 净利润；TTM / 静态；复权 | 同比环比混用；不同口径序列拼成一条分位曲线 |

质检发现的问题按 `ERROR`（确定错误，必须改）/ `WARNING`（需人工判断，写进风险段）/ `INFO`（口径差异，注明即可）标注，不静默修改。

## 5. 确定性与假设显式化

- **相同输入应得到相同结论**：脚本参数、风险档位映射、阈值一旦确定，不得在同一份输出里前后漂移。
- 缺失信息时**先追问**（一次最多 3 个问题），或显式写出假设并标注「假设，可纠正」；静默补一个数字是最严重的失败模式。
- 用户偏好与纪律上限冲突时，按纪律上限处理，并明确写出「哪项被调低了、为什么」，既不照办也不悄悄忽略。
- 所有阈值、比例、跌幅情景都要带一句「可调整的规划假设，非市场事实」。
- 结论必须给判断与置信度分层，不平铺 N 种可能让用户自选；同时主动点出最可能出错的假设与反向声音。

## 7. 工程自检（离线，可自动化）

`python scripts/self_test.py` 检查脚本语法、正常与边界场景、数据信封契约、文档与许可证文件完整性、免责声明模板存在性。它通过**只代表工程完整**，不能替代本文件的语义质检；发布新版本时应同时跑一遍两者。
