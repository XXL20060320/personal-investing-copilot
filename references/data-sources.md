# 数据源注册表与可复现记录（data-sources）

> 何时读：需要取行情 / 净值 / 财报 / 公告 / 规则数据，多个来源数字打架，用户问「这数据哪来的」，或准备输出结论前做数据质检。与 `data-and-compliance.md` 配套：那里管「能不能用、怎么标注」，这里管「从哪取、怎么记、取不到怎么办」。
>
> 本文改编自 Apache-2.0 项目 `china-stock-fund-analysis` 的数据源注册表与输出契约，按本 Skill 的起步配置主线重写；署名与许可证见 `THIRD_PARTY_NOTICES.md`。

## 1. 三条不可让渡的原则

1. **权威与便利分开**：交易所公告、基金定期报告、公司财报是最终引用依据；财经网站、聚合器、开源封装只是取数方便层。影响结论的关键数字，便利层必须回到一手来源或至少与第二个独立来源交叉验证。
2. **失败必须可见**：主来源失败时，写清「哪个源失败 → 换成了哪个源 → 置信度怎么变」。绝不把聚合器数字静默替换掉缺失的官方披露事实。
3. **可复现**：任何数值都能回答「哪天、从哪、以什么口径取的」。复现类任务保留原始文件 / 页面摘录、URL 与内容哈希。

## 2. 数据源分层

| 层级 | 用于 | 典型来源 | 使用规则 |
|---|---|---|---|
| L1 一手披露 | 财报、公告、基金合同与定期报告、产品规则、指数编制方案 | 巨潮资讯、上交所、深交所、北交所、证监会、基金管理人、指数公司 | 结论性事实优先引用这一层，标机构名 + 披露日 |
| L2 官方统计 | 宏观、利率、市场统计 | 国家统计局、人民银行、外汇局、交易所统计 | 检查发布日期、修订说明、季调口径 |
| L3 公开行情页 | 现价、历史价格、净值快照、折溢价 | 交易所行情页、东方财富、新浪财经、腾讯财经 | 注明取数时刻与交易状态；只作 L1 的补充与交叉验证 |
| L4 开源封装 | 批量取数、脚本化复现 | AKShare（MIT）、aktools（MIT，HTTP/MCP）、CNEquity（Apache-2.0，自托管数据湖）、yfinance（Apache-2.0，港美股）、edgartools（MIT，美股财报）、用户自有 token 的商用接口 | 尽量回溯到其背后的公开页面；记录**库名 + 版本 + 调用日期**；许可证与选型见 `references/open-source-toolchain.md` |
| L5 用户文件 | 券商导出、财报 PDF、持仓 Excel/CSV、截图 | 用户提供 | 记文件名 / sheet / 页码、单位、导出日期；截图需用户确认关键金额 |

本 Skill **不默认依赖 L4**：脚本不内置任何市场数据，也不要求用户安装第三方包。是否启用 AKShare / 商用接口由用户自行决定。

## 3. 常用数据族与必核字段

| 数据族 | 首选依据 | 必须同时记录 | 高频踩坑 |
|---|---|---|---|
| 证券身份 | 交易所 / 基金管理人 | 全称、标准代码、交易所、产品类型、上市状态 | 名称相似但跟踪指数不同；ETF 与场外联接混淆；杠杆/反向产品混入普通 ETF |
| 价格与成交 | 交易所行情页 / L3 | 取数时刻、盘前/盘中/盘后/休市、复权口径、币种 | 休市时把上一交易日收盘当「实时」；前复权价直接用于收益计算 |
| 基金/ETF | 基金合同、定期报告、管理人公告 | 规模口径、总费率、跟踪误差统计区间、净值日期、折溢价时点 | 用近一年涨跌幅冒充跟踪误差；把披露滞后的持仓当当前持仓；忽略 QDII 净值延迟 |
| 财务三表 | 公司年报/季报 | 报告期、披露日、合并/母公司、币种与单位、是否更正后版本 | 只看报告期不看披露日；归母与净利润混用；同比与环比混用 |
| 估值 | 指数公司 / 交易所 / 一手行情 | 样本区间、分位算法、PE/PB 口径（TTM 还是静态） | 3 年分位声称「历史高位」；不同口径序列拼接 |
| 规则与费用 | 券商、交易所、基金管理人公示 | 公示日期、适用品种、生效时间 | 凭记忆写最小交易单位、佣金、印花税、交收制度 —— **一律运行时核实** |

## 4. 标准化字段契约（数据信封）

脚本取数与用户文件解析统一使用 `scripts/data_envelope.py` 的 `DataEnvelope`，让「来源 + 时点 + 口径 + 质量」随数据一起走，而不是散落在对话文字里。

| 字段 | 含义 | 本 Skill 的用法 |
|---|---|---|
| `symbol_raw` / `symbol_normalized` | 原始代码 / 标准代码 | A 股 6 位 → `510300.SH`；港股 5 位；美股 ticker |
| `as_of` | 数据代表的时点 | 行情用行情时间戳，财报用报告期 |
| `disclosed_at` | 信息公开日 | 基本面与公告必填，避免前视偏差 |
| `provider` / `source_url` / `source_path` | 来源标识 | 用户文件写文件名 + sheet/page |
| `accessed_at` / `content_hash` | 访问日期、内容哈希 | 复现与比对用 |
| `adjustment` / `unit` / `currency` | 复权 / 单位 / 币种 | 元、万元、亿元必须显式 |
| `quality_flag` | `ok` / `partial` / `fallback` / `stale` / `conflicting` / `unverifiable` / `error` | 非 `ok` 时必须在研报「数据缺口」段说明 |
| `provider_chain` | 逐次尝试记录 | 失败与降级不得隐藏 |

用法：`python scripts/data_envelope.py --demo` 可查看一份示例信封（不联网、不读用户文件）。研报中至少把 `provider` + `as_of` + `accessed_at` + `quality_flag` 落到「数据表」的标注里。

## 5. 降级顺序

1. 换更窄的查询或直接下载文件，重试 L1。
2. 换同日期同字段的 L3 公开行情页交叉验证。
3. 用户已自行安装的 L4 封装（AKShare 等），记录版本与调用时间。
4. 用户提供的 L5 文件。
5. 仍不可得 → 明确写出缺口、已缩小的结论范围，以及「还需核实什么」。**不得编数，不得用「大约」掩盖缺口。**

每降一级，在 `provider_chain` 里追加一条，并把 `quality_flag` 从 `ok` 相应改为 `fallback` / `partial` / `unverifiable`；研报里对应下调置信度措辞。

## 6. 运行日志（Run log）

涉及取数的研报，在末尾「数据来源与运行记录」小节列出：

- 本次用到的来源清单（层级 + 名称 + URL 或文件名 + 访问日期）
- 执行过的脚本与关键参数（`allocation_calc.py` / `metrics_calc.py` / `quote_probe.py`）
- 失败的来源与降级决定
- 数据时点、交易状态、复权与单位口径
- 尚未核实的事项（对应 `Next checks`）

对话内可用紧凑列表呈现，不必输出完整 JSON 信封；但用户要求复现时，应能给出信封内容。

## 7. 公开行情端点（事实清单，可选能力）

以下端点为公开非登录接口，仅用于「用户明确询问现价 / 最新价」时补一层快照。端点域名与代码位数规则参考自 `asfamilybank/stock-query` 的 README / SKILL.md 事实性说明（该仓库许可证全文缺失，故未使用其任何代码，详见 `THIRD_PARTY_NOTICES.md`）。

| 用途 | 端点 | 说明 |
|---|---|---|
| A 股 / 场内 ETF / 指数快照 | `https://qt.gtimg.cn/q=` | 主用，代码前缀 `sh` / `sz`，返回 GBK 编码文本 |
| 港股快照 | `https://qt.gtimg.cn/q=` | 代码前缀 `hk` + 5 位（如 `hk00700`），同一端点、同样 `~` 分隔 |
| 美股快照 | `https://qt.gtimg.cn/q=` | 代码前缀 `us` + ticker（如 `usAAPL`），同一端点 |
| A 股快照备用 | `https://hq.sinajs.cn/list=` | 仅 A 股，通常需要 Referer，返回 GBK |

三个市场的字段位置不同，解析时按市场分支（以 2026-11 实测为准）：

| 字段 | A 股 | 港股 | 美股 |
|---|---|---|---|
| 最新价 | `parts[3]` | `parts[3]` | `parts[3]` |
| 昨收 | `parts[4]` | `parts[4]` | `parts[4]` |
| 行情时间 | 载荷中 14 位数字串 `YYYYMMDDhhmmss` | `parts[30]`（`YYYY/MM/DD hh:mm:ss`） | `parts[30]`（`YYYY-MM-DD hh:mm:ss`） |
| 币种 | `CNY`（按市场固定；载荷中另见 `parts[82]`） | `parts[75]`（通常 HKD） | `parts[35]`（通常 USD） |

代码规则：A 股与场内 ETF 为 6 位数字（沪市多为 5/6/9 开头，深市多为 0/1/2/3 开头）；港股 5 位数字（可写 `hk00700` / `00700.HK` / 裸 `00700`）；美股为字母 ticker。**这些是识别规则，不是产品身份证明**，产品类型仍按 `etf-screening.md` 第 0 步核对。字段位置可能随端点改版变化，`quote_probe.py` 只解析价格、昨收、名称、时间与币种，解析失败即返回 `unverifiable`；A 股时间由脚本在载荷中查找首个 14 位数字串得到，端点改版后须重新核对。

**时区口径（跨市场请求必须显式说明）**：A 股与港股时间戳为当地交易时间，美股时间戳通常为美东时间，三者的字符串格式虽被统一为 `YYYY-MM-DD hh:mm:ss`，但**不是同一时区、不能直接比较或当作同一时刻的快照**。混合市场时脚本只按字符串排序给出 `data_cutoff`，并在 `warnings` 中提示；研报须逐条标注市场、币种与时点，时区归属、交易状态与是否含盘后价格一律运行时核实。A 股「红涨绿跌」的颜色约定不适用于港股、美股。

硬性边界：

- `scripts/quote_probe.py` **默认不运行**，仅在用户明确要现价且环境允许联网时调用；只向上述端点发送标的代码，不发送持仓、账户、金额或任何个人信息。
- 返回为快照而非逐笔行情；休市时为最近一次收盘，必须标 `as_of` 与交易状态。
- 端点字段含义、限频策略、可用性均可能变化，**运行时核实**；解析失败返回 `unverifiable` 并回到 `data-and-compliance.md` 的检索路由，禁止用记忆里的价格补位。
- 不做历史 K 线、不做场外基金估值、不做下单，避免复权口径与净值延迟带来的误判。
- 涨跌显示遵循 A 股习惯：**涨红、跌绿**。

## 8. 数据质量门槛（分析前逐条过）

- [ ] 最新日期符合交易 / 披露节奏，休市与停牌已识别
- [ ] 复权口径与收益计算匹配，单位与币种统一
- [ ] 财务字段来自同一期间、同一报表口径、同一单位
- [ ] 基金持仓日期没有被当成当前持仓
- [ ] 基本面字段使用披露日而非仅报告期
- [ ] 关键数字至少有一个一手来源，或有两个独立来源交叉验证
- [ ] 派生指标能追溯到原始字段与公式
- [ ] 所有 `quality_flag ≠ ok` 的数据在研报中显式说明

未通过的项按 `references/release-gates.md` 的门控规则处理，不得带着未声明的缺口输出操作结论。
