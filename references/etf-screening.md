# ETF 筛选与同主题对比（etf-screening）

> 何时读：用户问「XX ETF 怎么样」「两只 ETF 选哪个」「帮我筛宽基 / 红利 / 低波 / 债券 ETF」，或需要为配置方案挑选具体标的时。涉及「贵不贵」时并行读 `valuation-and-entry.md`。
>
> 第 3.1 节的量化打分、第 4 节的折溢价口径分别参考 MIT 项目 `anchor-and-tilt`（League Table 与红旗校验）与 `himself65/finance-skills`（`etf-premium`），均按 A 股场内 / 起步阶段重写，未采用其美股标的与数值；署名见 `THIRD_PARTY_NOTICES.md`。

## 核心原则

先确认「这是什么产品」，再比较「哪个更合适」。**ETF 的名称相似不等于跟踪同一指数，代码相近不等于同一类产品**；个人投资者在起步阶段最该省掉的功夫是主题轮动，最该花功夫的是身份核对、费率、规模与跟踪质量。

## 1. 第 0 步：产品身份核对（不可跳过）

逐项核实并标注来源与时点：产品全称、场内代码（+A 股 6 位 / 港股 5 位等标准格式）、管理人、跟踪指数全称、产品类型（普通指数 / 增强 / QDII / 商品 / 杠杆 / 反向 / 结构化）、成立时间、上市交易所、申赎与交收规则。

- 港股类代码尤其要先确认是 ETF、杠杆产品、牛熊证还是结构化产品，再谈净值与估值。
- 名称含「ETF」「指数」「联接」的产品要分清场内 ETF 与场外联接基金，费率、门槛、交收都不同。
- 杠杆 / 反向产品存在每日再平衡机制，不适合长期持有；对阶段 A/B 用户默认排除，并说明原因。

## 2. 七维筛选

| 维度 | 判断什么 | 数据来源 | 常见坑 |
|---|---|---|---|
| ① 跟踪指数与编制规则 | 指数覆盖什么、如何选样与加权、行业集中度、是否含港股/美股 | 指数公司、基金招募说明书、基金定期报告（一手） | 名字叫「红利」但编制规则差异很大；不看编制规则就横向比收益 |
| ② 规模 | 是否具备持续运作的体量、是否接近基金合同约定的清盘条件 | 基金定期报告、基金管理人公告、交易所数据 | 规模过小有清盘与流动性风险；清盘条件以基金合同为准，不凭记忆给数值 |
| ③ 流动性 | 日均成交额、买卖价差、场内折溢价 | 交易所行情（注明时点与交易状态） | 只看单日放量；忽略价差导致的实际成本 |
| ④ 总费率 | 管理费 + 托管费 + 其他费用合计 | 基金合同、招募说明书 | 只比管理费忽略托管费与指数授权费；长期持有下费率差异会累积 |
| ⑤ 跟踪质量 | 跟踪误差、跟踪偏离、是否发生指数变更 | 基金定期报告 | 用「近一年涨跌幅」代替跟踪误差；不同基准不可直接比 |
| ⑥ 运作稳定性 | 成立年限、是否更换过管理人/指数、是否有大额申赎或暂停申赎公告 | 基金公告 | 新成立产品历史数据太短，无法评估跟踪质量 |
| ⑦ 组合角色与重合度 | 与已有持仓的成分重合、在三层桶里承担核心仓还是卫星仓 | 指数成分（需取数）+ 用户持仓 | 同时买 3 只高度重合的宽基/红利 ETF，误以为分散了 |

补充维度（用户问「贵不贵 / 现在能不能买」时）：指数层面 PE / PB 历史分位、股息率与股债相对性价比。**必须运行时取数并标注样本区间**，长周期优先（近 10 年 best，至少覆盖一轮完整周期），3 年分位不足以支撑「历史高位」判断。

## 3.1 逐项打分与红旗校验（让「更适合」可复核）

同主题比较 2–4 只时，先过门槛再逐项打分，避免用「综合更优」含糊收尾。

**第一步，硬门槛**：逐个确认产品身份（第 0 步）、代码真实有效、流动性足以容纳用户的单笔金额、关键数字有一手来源。任一不过 → 直接剔除并写明原因，不进入打分。

**第二步，逐项打分**：每个维度按「明显更优 +3 / 持平或无法区分 +1 / 明显更差 0」计分，乘以权重后加总。

| 维度 | 权重 | 说明 |
|---|---|---|
| 流动性（成交额 / 价差） | 3 | 接近否决项，门槛已在第一步过滤 |
| 规模与运作稳定性 | 3 | 关注清盘条件与成立时间，以基金合同 / 定期报告为准 |
| 总费率 | 3 | 管理费 + 托管费 + 其他费用合计，口径一致才能比 |
| 跟踪质量 | 2 | 跟踪误差与偏离，统计区间必须一致 |
| 组合角色与重合度 | 3 | 与用户现有持仓的匹配程度，重合度高应扣分 |

输出打分表并写明「权重与分档是可调整的规划假设，打分只是把判断显性化，不是精确模型，也不代表收益预测」。总分接近时按规模 → 费率 → 跟踪误差的顺序复核，并把分歧点明说，不要硬分高下。

**红旗清单（命中任一条即不输出「选 A」结论）**：

- 代码不存在、已终止、或产品类型被认错（场外联接 / LOF / 杠杆产品混入 ETF 表）。
- 关键数字（规模、费率、跟踪误差）只有媒体或聚合器二手来源，且未标「需核实原文」。
- 用近期涨跌幅排序当质量结论。
- 推荐的两只标的高度重合却被描述成「分散配置」。
- 单一标的超过预设上限却未说明。
- 跨境 / QDII / 商品类未核实场内溢价率与时点。

## 4. 跨境 / QDII / 商品类额外检查

额外核实：外汇额度与限购、场内溢价率（溢价高时买入等于额外付一笔溢价）、T+0 与交收规则、时区导致的净值滞后、汇率敞口、标的指数与境内指数的相关性、跟踪误差是否被汇率与费用放大。溢价率必须取实时或最近交易时点数据并标注，不得用「通常不高」带过。

## 5. 起步阶段的简化决策

- 阶段 A/B 用户：优先把长期钱配到 1–2 只覆盖广、费率与规模经核实、跟踪质量稳定的宽基或稳定器类 ETF，**不做行业主题轮动**，卫星仓比例保持很低。
- 标的比较控制在 2–4 只，不做长清单；清单越长越容易诱发频繁切换。
- 明确写出「本方案按〈数据截止时间〉的公开信息成立，若费率、规模、指数规则或跟踪质量变化需重新核对」。
- 对比结论不等于买入指令；买入节奏回到 `onboarding-and-allocation.md` 的分批路径。

## 6. 避坑

- 不用近期涨跌幅排序推荐 ETF，那是动量不是质量。
- 不把场外联接基金、LOF、杠杆产品混入 ETF 对比表。
- 不把媒体或第三方平台的二手数字当一手来源，标注「需核实原文」。
- 不忽略「同一指数多只产品」导致的重复配置。
- 不承诺跟踪误差会缩小、不承诺费率不变、不预测未来收益。
- 数据缺失时缩小结论范围：只比较拿得到数据的维度，并声明哪些维度未覆盖。

## 7. 建议骨架

30 秒结论 → 身份核对结果 → 七维对比表（含来源时点）→ 重合度与组合角色 → 条件化选择建议（条件 → 动作 → 失效条件）→ 需持续跟踪的公告与指标 → 风险与反向声音 → 免责声明（模板 A；含具体买入动作时用模板 B）。
